# Phase 1 Plan: EPUB Parsing and Database

## Goal and scope

EPUB files are accepted safely, read in EPUB spine order, and reproducibly
parsed into chapters and paragraphs with global positions. Books and parsing
results are stored in SQLite and exposed through a small API.

This phase does **not** implement AI extraction, the spoiler-filtered lookup
API, a reader UI, or accounts. A successfully parsed book has not yet been
fully analyzed; `ready` is reserved for completion of the later extraction
phase. Phase 1 requires an explicit `parsed` status.

## Implementation steps

1. **Database and migrations**
   - Set up SQLAlchemy models and Alembic configuration in `backend/`.
   - Create `books`, `chapters`, `paragraphs`, and `jobs` tables. Entities,
     facts, and relationships are added in Phase 2.
   - Define foreign keys, unique constraints, and indexes for book/chapter
     order and global paragraph positions.
   - Enable SQLite foreign-key enforcement and store the database file in the
     persistent Compose volume.
   - Provide a migration for an empty database and a migration test.

2. **EPUB parser**
   - Open EPUBs with `ebooklib`, use spine order as the canonical reading order,
     and extract available metadata such as title, author, and language.
   - Clean HTML into text with BeautifulSoup/lxml; skip empty chapters, retain
     meaningful paragraphs, and number paragraphs deterministically.
   - Assign each stored chapter a sequential chapter index and the inclusive
     position range of its paragraphs.
   - Give each stored paragraph a book-wide unique, contiguous position
     starting at 0. Positions are generated by the server only.
   - Parse EPUBs without external network access. Limit upload size and
     expanded data size; reject malformed archives, encrypted/DRM-protected
     files, and unsupported EPUBs with clear errors.

3. **Upload and persistence**
   - `POST /books` accepts an EPUB file as `multipart/form-data` and assigns a
     stable book ID and SHA-256 source hash.
   - Parsing and persistence are transactional: on failure, no partial
     chapters or paragraphs remain, and the book is marked `error` with a
     safe, user-readable message.
   - Status transitions for this phase are `uploaded -> parsing -> parsed` or
     `uploaded/parsing -> error`. Re-uploading the same file must not cause
     unintended duplicate processing; define duplicate-upload UX based on the
     source hash.
   - Do not permanently store the original EPUB unless a re-parsing or
     download use case requires it; document this storage decision before
     implementation.

4. **Reading API and error handling**
   - `GET /books` returns library metadata and processing status.
   - `GET /books/{id}` returns metadata and parsing status.
   - `GET /books/{id}/chapters` returns chapters in reading order with position
     ranges.
   - `GET /books/{id}/content/{chapter_id}` returns paragraphs ordered by
     position. Unknown IDs return a consistent 404 error.
   - OpenAPI schemas describe uploads, responses, and errors. Do not expose
     absolute server paths or internal stack traces in API errors.

5. **Configuration and operations**
   - Read the database URL and EPUB limits from centralized settings; Compose
     must preserve data across restarts.
   - Make upload size (default 50 MB, allowed range 1–500 MB), expanded EPUB
     size (default 250 MB, range 1–2000 MB), and archive-entry count (default
     5000, range 1–50000) configurable.
   - Make the temporary multipart-upload directory configurable through
     `UPLOAD_TEMP_DIR`; discard upload spool files after the request.
   - Document required environment variables, migrations, and parser limits in
     the README. A parser timeout is not configurable yet.

## Planned tests

- **Position invariants:** positions start at 0, are globally unique,
  contiguous, and strictly increasing; chapter ranges exactly match their
  paragraphs.
- **Spine order:** a small synthetic EPUB with multiple XHTML files in a
  deliberately different filesystem order produces chapters in spine order.
- **Text cleanup:** headings, paragraphs, entities, and empty HTML elements
  are handled as expected; empty chapters do not create position gaps.
- **Error cases:** malformed/non-EPUB archives, missing container or OPF
  documents, encrypted content, and exceeded limits produce clear 4xx errors
  and leave no partial data.
- **Database:** migrations work on an empty SQLite database; constraints and
  foreign keys are checked.
- **API:** upload and retrieve a book, chapters, and content; unknown
  book/chapter IDs and invalid uploads return defined error responses.
- **Persistence:** stored data remains after closing and reopening the
  database.

Test files should be synthetic or public-domain and small; do not check in
copyrighted book text.

## Acceptance criteria

- A valid test EPUB uploads, parses in the correct spine order, and is stored
  with status `parsed`.
- Paragraph positions form an exactly contiguous, monotonically increasing
  sequence starting at 0; chapter boundaries correctly cover their
  paragraphs.
- Invalid, DRM-protected, or oversized uploads are rejected with clear errors
  and leave no partial parser data.
- Migrations work on an empty database, and stored data survives a backend
  restart.
- Backend tests and Ruff pass locally and in pull-request CI.
- The phase ends before AI extraction or the frontend reader is implemented.

## Decisions made before implementation

- Identical uploads are handled idempotently using the SHA-256 hash and return
  the existing book record.
- Maximum upload size, maximum expanded EPUB size, and parser timeout.
- The source EPUB is not stored permanently; extracted chapters and paragraphs
  are stored instead. A future re-parsing use case would require another
  upload.
